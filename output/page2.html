My family and I moved back home to Kentucky from Los Angeles. It gave me more time with my dad before his sudden death.

📅 Nov 01, 2026  |  Category: Business  |  Read Source →
The author is glad her son got more time with his grandfather.

Courtesy of Tonilyn Hornung

  • My husband and I moved back to Kentucky from Los Angeles eight years ago.
  • I wanted to be closer to family, and for my son to get more time with his grandparents.
  • When my dad suddenly passed away four years ago, I was even more grateful for that time.

Eight years ago, my husband and I decided to move our family from California to Kentucky. On days we miss our LA favorites, like animal fries from In-N-Out Burger or warm sunshine when it's dreary and 22 degrees, we play the game: What would life be like if we stayed? It starts out breezy with talk of Disneyland rides and running into celebrities like Harry Connick Jr., but the conversation never lasts too long.

"If we stayed," I say softly, "I would've missed out on time with my dad."

When we lived on the other side of the country, we had less time together

That's when the fun stops, and my husband reaches for my hand. We spent our first four years in Louisville living 15 minutes away from my parents, and then my father died unexpectedly. If we had stayed in LA, family time would've been reduced to two weeks a year and short phone calls. I couldn't have predicted that coming back home would give us such a gift — more time with my dad. And it almost didn't happen.

Committing to a cross-country move was no small thing. This was why I hadn't packed up our house in the middle of a no-sleeping week during my son's colicky fourth trimester. I was ready for family dinners, sleepovers, and the support I'd craved since our kiddo was born. But even though I felt ready, my husband needed time. A big move meant big changes in careers and friends. So, we waited and considered while our kid moved out of diapers and into Pull-Ups.

I continued calling and FaceTiming my parents so I could feel more connected. And this is how our nightly story time chats became a ritual — until my son started asking to see his grandparents during the day, too.

One particular afternoon, my toddler said, "Call Papa?" So I phoned my dad at work because he always answered. After talking to his grandson about Legos, we finalized a time for an upcoming visit. That's when I confided that I was nervous that a move home wasn't in our future. With more confidence in me than I had in myself, he said gently, "You'll know when it's right." Since my dad was, you know…my dad, I believed him.

We decided to move back to Kentucky at the right time

Five years after our son was born and many discussions later, my husband and I finally found the right time — just before our son entered Kindergarten. My dad was right. Once we were back in Louisville, it took maybe two full days to realize that being home did not disappoint. I could feel my body relax in a way it hadn't for years. Moving home gave me the safety I was looking for. For my son, the closeness was life-changing in all the best ways.

"Papa, can you make soup?"

Basically, from the moment we moved, my son was obsessed with my dad's homemade chicken soup. It was an ordeal to prepare, but without fail, my father cooked it whenever his grandson asked. But that's not the only Papa-related craze my kid leaned into once we were home. Games of hide-and-seek, walks around the lake, making paper airplanes, and Papa's pancakes were a few of the favorites my kid loved about visiting his grandfather.

The best was after our weekly dinners, my son and I would climb into our car, and wave goodbye to my mom and dad from the driveway. As we drove out through the neighborhood and turned the corner, my dad would magically appear on the sidewalk, waving again. My son was astounded and laughed so hard, shouting, "Papa, how did you do that?!" I never told my kid that his grandfather had simply run through two backyards to catch us. I was happy to let him believe his Papa was magic.

Moving home gave us all more than we knew we needed — time together. Countless memories were made that wouldn't have happened had we stayed. Those taken-for-granted, everyday moments of homemade soup and silly waves are forever part of us. In the four years since my dad's sudden heart attack, this is what's helped us through our shock and grief. Our lives wouldn't be as full without them.

I made my coding agent explain its own pull requests

📅 Nov 01, 2026  |  Category: Technology  |  Read Source →

The problem: the agent knows why, the reviewer doesn't

More and more of the pull requests I review were written by a coding agent. The code is usually fine. Reviewing it is not: I open Files changed, see 400 lines across 12 files, and start reverse-engineering the reasons behind each block.

The funny part is that the agent knew those reasons. It had just made every decision. By the time a human opens the diff, that context is gone.

I tried asking the agent to write PR comments. That works, but every comment pings the whole team, the agent's text mixes with the human discussion, and it all stays in the PR forever.

So I built DiffNotes.

What a good note looks like

A note is a short, plain-language "why" attached to a changed block:

On top of the diff, a summary box shows what the PR does, the deploy steps, and where to look hardest:

Notes can carry screenshots (before/after, mobile/desktop), Markdown reports, CSVs and small HTML demos that run in a sandbox right under the note.

Setup in about 5 minutes

1. A server. Use the free hosted one at diffnotes.dev (sign in with GitHub), or run your own:

docker run -d -p 3000:3000 -v diffnotes:/data \ -e ADMIN_EMAIL=you@company.com -e PUBLIC_URL=https://reviews.example.com \ ghcr.io/igorkasyanchuk/diffnotes

2. The skill, on each developer machine. The welcome page gives you this command with your token already filled in:

curl -fsSL https://diffnotes.dev/install.sh | DIFFNOTES_SETUP_TOKEN=dn_… sh

It installs an Agent Skill that Claude Code, Codex, Cursor and other skills-aware agents pick up. If your agent speaks MCP instead:

claude mcp add --transport http diffnotes https://diffnotes.dev/mcp \ --header "Authorization: Bearer $DIFFNOTES_TOKEN"

3. The extension for reviewers: Chrome Web Store. It opens a tab on install: enter your server, sign in, done.

Ask the agent

When the PR is ready:

annotate this PR with diffnotes

The agent reads its own diff and uploads:

  • a summary of the PR
  • a deploy card (migrations, flags, rollback)
  • a risk list: which spots deserve the closest look
  • one note per changed block, explaining why, not restating what
  • screenshots or a small demo when the UI changed

You can add per-repository rules in a .diffnotes.yml on the base branch, for example "every migration needs a deploy note". The agent reads them before writing.

What reviewers see

Open Files changed. The extension draws the notes next to the lines. Scroll away and a small dock keeps the note count and a switch to hide everything. Images open in a gallery; a demo expands to phone, tablet or desktop width.

Try it without installing anything: diffnotes.dev/demo.

Why nothing is posted to GitHub

  • No noise. The PR conversation stays human.
  • Privacy. Notes live on your server. Only members of the account that owns the repository can read them.
  • They expire. Explanations of a diff are useful during review, not forever.

What's next

DiffNotes is MIT and small on purpose: one container, SQLite, two runtime dependencies. If your team reviews AI-written code, I'd love to hear what would make those reviews faster.

JavaScript (ES6+) for React Developers: The Definitive Guide

📅 Nov 01, 2026  |  Category: Technology  |  Read Source →

React is fundamentally plain JavaScript. If you ever struggle with state updates, unintended re-renders, or props drilling, the issue is rarely React itself—it is usually a missing piece of modern ECMAScript fundamentals.

  1. Modern Variables: const, let, Scoping, and Retiring var In legacy JavaScript, var was function-scoped and subject to unpredictable hoisting behaviors:
JavaScript // The legacy problem: var leaks out of block statements if (true) { var framework = "React"; } console.log(framework); // "React" (escaped block scope)

Modern JS introduces block scoping with let and const:

const: Enforces constant references. Variables cannot be reassigned. Use this by default (roughly 95% of the time in React components).

let: Enables reassignable block-scoped variables (ideal for counters, loops, or flags).

Temporal Dead Zone (TDZ): Unlike var, accessing let or const before declaration throws a ReferenceError rather than returning undefined.

JavaScript / / Modern standard: const API_URL = "https://api.store.com/v1"; let retryCount = 0; if (retryCount === 0) { const localMessage = "Initial attempt"; retryCount += 1; } // localMessage is completely inaccessible here (ReferenceError)
  1. Arrow Functions and Lexical this Arrow functions (() => {}) give developers a concise syntax and, more crucially, lexical this scoping. They do not bind their own this, arguments, or super.

Concise Syntax & Implicit Returns
In React, implicit returns are frequently used for rendering JSX:

JavaScript // Explicit return const UserCard = (props) => { return <div>{props.name}</div>; }; // Implicit return (no 'return' keyword, wrapped in parentheses) const UserCard = ({ name }) => ( <div className="card"> <h3>{name}</h3> </div> );

Lexical this vs Standard Functions
In traditional functions, this is determined by how the function is invoked. With arrow functions, this is bound to the surrounding lexical context:

JavaScript const counterService = { count: 0, start() { // Normal function inside setInterval would rebind 'this' to window/timeout setInterval(() => { this.count++; console.log(`Live Count: ${this.count}`); }, 1000); } };
  1. Essential Array Methods: map, filter, reduce, find, some/every


JavaScript const products = [ { id: "p1", title: "Wireless Mouse", price: 30, inStock: true }, { id: "p2", title: "Mechanical Keyboard", price: 120, inStock: false }, { id: "p3", title: "USB-C Hub", price: 45, inStock: true } ]; // 1. filter: Available items only const available = products.filter(p => p.inStock); // 2. map: Transform to rendered strings / components const catalogView = available.map(p => `${p.title} - $${p.price}`); // 3. reduce: Calculate aggregate total const inventoryValue = products.reduce((sum, p) => sum + p.price, 0); // 4. find: Grab exact target const keyboard = products.find(p => p.id === "p2"); // 5. some: Availability check const hasOutOfStock = products.some(p => !p.inStock); // true
  1. Destructuring (Arrays & Objects) and Default Parameters

Destructuring provides syntactic shortcuts to extract nested values directly into clean variables.
Object Destructuring in Props

JavaScript

// Instead of accessing props.theme, props.title, props.isActive function Button({ theme = "primary", title = "Submit", onClick }) { return ( <button className={`btn btn-${theme}`} onClick={onClick}> {title} </button> ); }

Array DestructuringArray destructuring maps variables based on positional indexing (the exact mechanism powering React's useState hook):

JavaScript const [selectedTab, setSelectedTab] = ["overview", () => {}];
  1. Rest and Spread Operators (...) While both use three dots (...), their intents are distinct: Spread Operator (...): Expands elements of an array or properties of an object into a new structure. Rest Parameter (...args): Condenses multiple distinct arguments into a single collected array. Immutable State Updates with Spread Never mutate React state directly; always create new copies:
JavaScript const userProfile = { id: 101, name: "Ali", settings: { dark: true } }; // Updating user profile immutably const updatedProfile = { ...userProfile, name: "Alireza", // overrides 'name' role: "Admin" // appends new field }; // Adding an item to an array immutably const cart = ["Mouse", "Keyboard"]; const nextCart = [...cart, "Monitor"];

Rest Parameter in Components

JavaScript // Collect rest of props to pass through to native elements const CustomInput = ({ label, ...nativeInputProps }) => ( <label> {label} <input {...nativeInputProps} /> </label> );
  1. Immutability: Shallow vs Deep Comparison React optimizes renders using shallow equality comparison (Object.is() / ===).

Shallow Copy / Comparison: Compares only top-level references. If an object reference hasn't changed, React assumes its internals haven't changed either.

The Mutation Trap:

JavaScript // WRONG: Direct mutation does NOT change object reference! const state = { count: 0, meta: { tags: ["tech"] } }; state.count = 1; // If passed to a memoized component or setState: // previousState === nextState evaluated to TRUE -> NO RE-RENDER! // RIGHT: Shallow copy creates a new top-level reference const nextState = { ...state, count: 1 }; console.log(state === nextState); // false -> triggers re-render // Nested reference gotcha: // state.meta and nextState.meta still point to the EXACT SAME memory address! // For nested mutations, you must shallow copy the inner object as well: const fullyUpdated = { ...state, meta: { ...state.meta, tags: [...state.meta.tags, "react"] } };
  1. Async JavaScript: Promises and async/await with try/catch React lifecycles and event handlers communicate with network APIs via asynchronous promises.
JavaScript // Standard data fetching pattern with async/await and try/catch async function fetchProducts(category) { try { const response = await fetch(`https://api.store.com/products?category=${category}`); if (!response.ok) { throw new Error(`HTTP Error: ${response.status}`); } const data = await response.json(); return { success: true, payload: data }; } catch (error) { console.error("Fetch pipeline failed:", error.message); return { success: false, error: error.message }; } finally { console.log("Network request completed."); } }
  1. Modular Architecture: Named vs Default Exports JavaScript modules (ESM) enable decoupled, maintainable codebases:
JavaScript // mathUtils.js export const TAX_RATE = 0.09; // Named Export export const formatCurrency = (val) => `$${val.toFixed(2)}`; // Named Export export default class CartEngine {} // Default Export JavaScript // Consumer.js import CartEngine, { TAX_RATE, formatCurrency } from './mathUtils.js';
